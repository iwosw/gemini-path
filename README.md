# GeminiPath (Windows)

Точечная диагностика соединения и экспериментальный обход **сетевого DPI** для сайта Gemini, Gemini CLI и Antigravity на Windows 10/11 x64. Без внешнего сервера и без установки VPN. Работающий движок — [GoodbyeDPI 0.2.2](https://github.com/ValdikSS/GoodbyeDPI), который используется по лицензии [Apache-2.0](https://github.com/ValdikSS/GoodbyeDPI/blob/0.2.2/LICENSE); драйвер WinDivert поставляется разработчиком движка. Этот репозиторий содержит настройку и управление, а не собственную реализацию драйвера.

**Важно:** обход DPI не меняет ваш публичный IP, регион аккаунта, права доступа или лимиты Google. [Antigravity доступен только в перечисленных Google странах](https://antigravity.google/docs/faq/); РФ в перечне отсутствует. Если блокирует сам сервис, режимы `split`/`fake` ничего не исправят. Если сегодня всё работает, сначала сохраните результаты диагностики, затем сравните их при следующем сбое.

## Быстрый старт

**Для Antigravity — откройте `AntigravityPatcher.cmd` двойным щелчком.** Откроется отдельное окно со статусом, выбором файла и кнопками «Проверить», «Применить патч», «Откатить». Нужен Python 3.10+ с Tkinter (обычная установка Python для Windows). Это экспериментальный **клиентский** патч; для сетевой диагностики используйте команды ниже.

1. Скачайте репозиторий ZIP через GitHub (**Code → Download ZIP**) и распакуйте в папку, которой доверяете. Нужны Windows 10/11 x64, PowerShell 5.1 и права администратора **только для запуска/остановки движка**.
2. Выполните `GeminiPath.cmd doctor`. Проверьте вывод до запуска программы. `example.com` — контрольный адрес, чтобы отличить общий сбой сети. Диагностика делает прямые запросы, не используя системный HTTP-прокси.
3. Выполните `GeminiPath.cmd install`: загрузится официальный архив GoodbyeDPI 0.2.2, перед распаковкой проверяется закреплённый SHA-256 `00A2F8B99CD817F8C7FC4C449033015F039D18AF213DE78CB66BF202277C0628`. Файлы будут только в `vendor/`, который не попадает в Git.
4. Откройте **Командную строку от имени администратора**, перейдите в папку проекта и запустите `GeminiPath.cmd start`. Движок работает только пока открыт его процесс; автозапуск, служба, смена DNS, прокси или системных настроек не создаются.
5. Повторите `GeminiPath.cmd doctor`, обновите вкладку Gemini и проверьте работу CLI/Antigravity **в приложениях**. Если не помогло, выполните `GeminiPath.cmd stop`, затем `GeminiPath.cmd start -Mode fake`. В любой момент `GeminiPath.cmd stop` останавливает процесс, запущенный этим проектом.

| Команда | Что делает |
| --- | --- |
| `GeminiPath.cmd doctor` | DNS, TCP:443 и HTTPS для контрольного и целевых доменов; не требует входа в аккаунт |
| `GeminiPath.cmd install` | Скачать, сверить SHA-256 и распаковать движок |
| `GeminiPath.cmd start` | Фрагментация TLS ClientHello для доменов из `domains.txt` |
| `GeminiPath.cmd start -Mode fake` | Дополнительно отправка ложных запросов с неверным checksum/SEQ, если простой режим не помог |
| `GeminiPath.cmd status` | Проверить запущенный процесс |
| `GeminiPath.cmd stop` | Остановить только процесс проекта |
| `GeminiPath.cmd ag-scan` | Прочитать локальный Antigravity и проверить известную сигнатуру клиентской проверки |
| `GeminiPath.cmd ag-patch` | **Эксперимент:** сохранить оригинал и изменить ровно одну проверенную инструкцию `language_server.exe` |
| `GeminiPath.cmd ag-restore` | Вернуть оригинал, только если файл с момента патча не менялся |

`domains.txt` — список хостов без `https://`, пути и подстановок `*`. GoodbyeDPI применяет записи и к поддоменам. Начальный набор покрывает Gemini и известные точки авторизации/API, но сервис может менять адреса. Добавляйте хосты **только после диагностики**, затем перезапускайте режим. Движок перехватывает TCP 80/443 на сетевом уровне и фильтрует по HTTP Host/TLS SNI; он не ограничен отдельным браузером/процессом и не умеет обработать соединения без видимого имени сервера. Остальной TCP-трафик через фильтр проходит без изменения. Программа не читает пароли или содержание зашифрованных чатов.

### Если диагностике всё «ok», а чат не открывается

- `HTTP 200/302/403/404` в диагностике означает только ответ HTTPS-адреса, **не успешное выполнение запроса к модели**. Код `403/451` сам по себе не раскрывает причину; если приложение прямо пишет о регионе/недоступности аккаунта, DPI-режим этого не исправит.
- Chromium может использовать HTTP/3 по UDP/443 (QUIC), который этот точечный TCP-режим не обрабатывает. Для проверки временно отключите QUIC **в используемом браузере** и перезапустите его; затем верните настройку обратно. Gemini CLI обычно использует HTTPS/TCP, а Antigravity может использовать собственный сетевой стек, поэтому проверяйте его отдельно.
- При DNS `failed/timeout` исправлять нужно разрешение имени; этот проект DNS не меняет. При `example.com` = `failed` проверьте само соединение. Если активен другой перехватчик трафика, остановите его на время проверки.
- При проблеме с драйвером проверьте окно движка: WinDivert может быть несовместим с другим перехватчиком. Не отключайте защиту Windows ради запуска. Удаление папки `vendor/` после остановки убирает скачанные компоненты.

### Эксперимент с клиентской проверкой Antigravity

Обнаружен [локальный x64-патч проверки в языковом сервере Antigravity](https://github.com/vezlin1/antigravity-bypass-russia/blob/main/src/core/opcodes.rs). На Antigravity **2.8.1** сигнатура встретилась один раз при чтении файла; это **не является подтверждением**, что генерация с отклонённым Google аккаунтом заработает. Если проблема действительно в клиентском запрете, а не в ответе сервера, можно попробовать отдельный режим:

1. Установите Python 3.10+ (на этой машине проверено с 3.13). Запустите `GeminiPath.cmd ag-scan` — это только чтение файла. Поддерживается стандартная установка Antigravity для Windows x64 в `%LOCALAPPDATA%\Programs\Antigravity`.
2. **Полностью закройте Antigravity.** Запустите `GeminiPath.cmd ag-patch`; программа проверит формат PE и наличие **ровно одной** сигнатуры в секции `.text`, запишет исходный SHA-256 и резервную копию в `vendor/patches/`, затем атомарно заменит исполняемый файл. Windows может запросить права на запись в папку приложения.
3. Запустите Antigravity и проверьте реальную генерацию. Для отмены закройте приложение и запустите `GeminiPath.cmd ag-restore`. После обновления приложения патч нужно проверять заново; если версия изменилась, откат намеренно не перезапишет обновлённый файл.

Подписанный исполняемый файл **утрачивает действительность цифровой подписи после изменения**; приложение или защита ОС могут отказаться запускать его. Патч не меняет ответы серверов Google и не снимает серверные ограничения региона, тарифа или аккаунта. Он не нужен для сайта Gemini и не патчит старый Gemini CLI. Не удаляйте `vendor/patches/`, пока не откатили эксперимент. Тесты используют искусственный файл и копию установленного Antigravity; сам установленный файл тесты не изменяют.

**Бесплатный внешний узел без VPN для всей Windows:** см. [сравнение вариантов](docs/free-egress.md) и [опытный Cloudflare Worker для Antigravity CLI в режиме Gemini API key](worker/README.md). Этот шлюз не является прокси для сайта Gemini или десктопной IDE.

**О старом Gemini CLI:** [с 18 июня 2026 вход личных аккаунтов через «Login with Google» прекращён](https://developers.google.com/gemini-code-assist/docs/deprecations/code-assist-individuals); клиентский патч или DPI не вернут эту возможность. Google предлагает переход на Antigravity CLI; отдельно задокументирован [режим его запуска с ключом Gemini API](https://antigravity.google/docs/cli/install/#using-a-gemini-api-key), у API есть собственные региональные ограничения.

## Архитектура и границы

```
GeminiPath.cmd → GeminiPath.ps1 → диагностика DNS/TCP/HTTPS
                                → проверенная загрузка GoodbyeDPI
                                → WinDivert + доменный список TCP/TLS
```

Защита от поломок: простой режим по умолчанию, список доменов, проверка запущенного PID и пути перед остановкой, никакой службы/постоянного сетевого профиля. Режим `fake` включается только вручную. Глобальная блокировка QUIC (`-q`) намеренно не включена, потому что она затронула бы всю Windows. Клиентский бинарный патч отдельный и необязательный.

У «решений без VPN» может быть внешняя инфраструктура под капотом: например, [публичные SmartDNS/SNI-прокси](https://github.com/vezlin1/antigravity-bypass-russia/blob/main/src/net/resolvers.rs) или [Cloudflare Worker](https://github.com/Renkiy/Antigravity-Unlock/blob/main/tools/cloudflare_worker.js). Сам локальный патч не создаёт новый зарубежный IP-адрес. При серверном отказе с российского IP без какого-либо иного выхода нельзя обещать разблокировку одним изменением приложения.

### Мобильные устройства — следующая стадия

Android без root: возможен локальный `VpnService` для выборочной обработки трафика **без внешнего VPN-сервера**, но значок VPN появится. iPhone без jailbreak: приложение не может незаметно менять пакеты Safari/чужих приложений; для обработки всего трафика потребуется разрешённый Apple Network Extension/VPN-интерфейс либо решение на своём роутере. Вариант без сервера **и без значка VPN на iPhone** для произвольных приложений как обещание не даём.
