# Gemini в браузере без VPN-подписки — эксперимент

Для ошибки **«Недоступно в вашем регионе» при российском IP** обычная фрагментация TLS не меняет адрес, который видит Google. В GeminiPath есть отдельная кнопка **«Открыть Gemini в браузере»**: она запускает Chrome/Edge с отдельным профилем и направляет `gemini.google.com` и `accounts.google.com` через [публичный SNI-шлюз, используемый для Gemini](https://github.com/Renkiy/Antigravity-Unlock/blob/main/tools/pin_hosts.py). Весь остальной трафик браузера идёт напрямую. Настройки Windows, основного браузера, DNS, `hosts` и VPN не меняются.

## Как попробовать

1. Запустите [GeminiPath](../README.md#установка-за-минуту) и нажмите **«Открыть Gemini в браузере»**. Программа сначала установит TLS-соединение с обоими Google-хостами через шлюз и проверит сертификат доверенным системным центром. Если шлюз недоступен или сертификат неверный, браузер не запустится.
2. Откроется **новый пустой профиль Chrome/Edge**. Войдите в Google непосредственно на `accounts.google.com`, затем отправьте сообщение на `gemini.google.com/app`. Основной профиль и сохранённые в нём cookies не переносятся.
3. Для выключения маршрута закройте это окно браузера; обычный Chrome/Edge продолжит работать как раньше. Данные отдельного профиля лежат в `%LOCALAPPDATA%\GeminiPath\browser-profile`; их можно удалить после выхода из Google и закрытия окна.

Команда без GUI: `py browser_route.py check`, затем `py browser_route.py open` из исходников проекта. Нужен Python 3.10+; в установщике Python уже включён. Шлюз в коде — публичный адрес `45.88.174.254`. На момент разработки анонимные проверки `gemini.google.com` и `accounts.google.com` через него получали ответы Google с валидным TLS, **но вход в аккаунт и работа чата этим не подтверждены**.

## Что важно для понимания

- **Без VPN-подписки ≠ без внешнего узла.** Бесплатный SNI-шлюз — чужой сетевой узел. Он видит домены, время и объём соединений. Он не должен видеть содержимое HTTPS, пока браузер проверяет оригинальный сертификат Google; GeminiPath не устанавливает дополнительный корневой сертификат и не отключает проверку TLS.
- Шлюз или Google могут перестать принимать этот маршрут. Публичный IP и доступность зависят от оператора шлюза. Если после входа всё ещё появляется региональный отказ или чат не отвечает, **пробный маршрут не помог**; не стоит скрывать ошибку патчем интерфейса.
- IP в `browser_route.py` — **адрес шлюза**, а не обещание конкретной страны выхода. Проверка сертификата говорит только о целостности HTTPS, не о регионе, правах аккаунта или результате генерации.
- Этот маршрут касается **только отдельного окна сайта**. Устаревший Gemini CLI и десктопная Antigravity используют другие сетевые стеки; см. [сравнение вариантов](free-egress.md).
