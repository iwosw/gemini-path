# Бесплатный внешний выход без системного VPN: карта вариантов

## Что считать «без VPN»

Раздельно проверяем три свойства: нет VPN-интерфейса Windows; нет **своего** сервера; вообще нет **чужого** сетевого узла. Последние два несовместимы с требованием изменить регион видимого Google исходящего IP: если запрос дошёл до Google напрямую, сервер видит исходный маршрут. DNS или клиентский патч сами по себе не создают зарубежный выход.

| Сценарий | Бесплатный кандидат | Что проверить |
| --- | --- | --- |
| Только сетевой DPI | Встроенный режим GeminiPath (`split`/`fake`) | Выполнить запрос до/после; IP и страна аккаунта не изменятся |
| Внутренняя проверка Antigravity | Отдельный GUI-патч Antigravity | Реальную генерацию, а не исчезновение баннера |
| **Antigravity CLI с Gemini API-ключом** | [Свой Cloudflare Worker Free](../worker/README.md) | Модельный запрос через endpoint, регион и пригодность ключа |
| Сайт Gemini / вход в аккаунт / вся IDE | Публичный SNI-шлюз от стороннего SmartDNS или собственный полноценный CONNECT-выход | Пригодность выхода, TLS-сертификат Google и реальный вход/ответ; внешний узел есть |

**Кандидат без своего сервера:** проекты [antigravity-bypass-russia](https://github.com/vezlin1/antigravity-bypass-russia/blob/main/src/net/resolvers.rs) и [Antigravity-Unlock](https://github.com/Renkiy/Antigravity-Unlock/blob/main/tools/pin_hosts.py) используют публичные SmartDNS/SNI-шлюзы для отдельных доменов. Это не VPN-клиент и не арендованный вами VPS, но это **чужой внешний сетевой узел**, зависящий от его доступности. Не стоит копировать чужие IP в `hosts` без проверки TLS, живости, отката и набора доменов: такой шаг меняет разрешение имён во всей Windows. Для следующей версии GeminiPath лучше исследовать отдельный браузерный профиль и приложение-специфичное направление трафика, не постоянную правку системных DNS/hosts.

**Свой бесплатный управляемый узел:** Worker проще VPS и позволяет через официальный `GOOGLE_GEMINI_BASE_URL` направить **только модельные запросы Antigravity CLI в режиме Gemini API key**. В нём фиксирован один upstream Google API, чужие ключи отклоняются, исходные ошибки Google сохраняются. Для сайта и IDE он не заменяет полноценный прокси: [входящие TCP CONNECT в Workers недоступны](https://developers.cloudflare.com/workers/runtime-apis/tcp-sockets/#considerations). Чтобы гарантированно направить **все** их соединения через другой выход, нужен другой механизм/узел и проверка каждой сетевой компоненты.

### Как принять решение по результату

1. Если `doctor` проходит, а приложение сообщает `ineligible`/неподдерживаемый регион, проверка сетевой достижимости ничего не доказывает: смотрите точный ответ при реальной отправке запроса.
2. Если после клиентского патча остаётся отказ модели, нужен подходящий **серверный** маршрут или устранение причины отказа аккаунта; менять ещё больше байтов наугад бессмысленно.
3. Для CLI сначала проверьте [региональную доступность Gemini API](https://ai.google.dev/gemini-api/docs/available-regions) и [официальный режим API-ключа Antigravity CLI](https://antigravity.google/docs/cli/install/#using-a-gemini-api-key). Даже рабочий Worker не отменяет ограничения ключа, возраста, тарифа и аккаунта.

Чтобы принять решение о едином варианте для **сайта + IDE** нужны данные реальной неудачной попытки (какой клиент, текст ошибки, HTTP-код без токенов) и проверка, доступен ли выбранный публичный SNI-шлюз сейчас. Без этих данных обещание «одной кнопкой для всех» непроверяемо.
